# AI Review Analyst

Бот, который читает отзывы на Wildberries и выжимает из них суть. Кидаешь артикул — получаешь **топ-3 проблемы и топ-3 преимущества товара**, выделенные нейросетью из последних 50 отзывов.

Сделано по ТЗ: aiogram + httpx + LLM (YandexGPT или OpenAI) + pydantic для строгой валидации JSON.

## Команды

- `/analyze 12345678` — анализ по артикулу (или `/analyze https://www.wildberries.ru/catalog/...`)
- `/model` — какая цепочка LLM-провайдеров сейчас активна
- `/cache` — сколько отзывов лежит в кэше

## Как это работает

1. Парсим последние `MAX_REVIEWS` (50) отзывов с публичного API WB;
2. Отправляем их LLM с промптом «выдели топ-3 проблемы и топ-3 преимущества»;
3. Нейросеть должна вернуть **строгий JSON** (поля `pros`, `cons`, ...);
4. JSON валидируется через pydantic — если нейросеть сочинила что-то своё, бот не падает, а **переспрашивает** её с пояснением, что именно не так (`LLM_MAX_RETRIES=2`);
5. Результат — красивым сообщением, а отзывы кэшируются на 5 минут, чтобы не дёргать API на каждый запрос.

## Почему «цепочка провайдеров»

Модель не обязана быть одна. В `config.py` задан основной провайдер и резервные (`LLM_FALLBACKS`). Если у YandexGPT кончился лимит или ключ невалидный — бот автоматически пробует следующего. Для разработки есть `LLM_PROVIDER=mock`: без единого ключа, нейросеть имитируется локально, и можно гонять тесты и показывать демо где угодно.

## Запуск

```bash
python -m venv .venv
pip install -r requirements.txt
export WB_BOT_TOKEN=123456:ABC...   # токен от @BotFather
export LLM_PROVIDER=mock            # mock | yandex | openai
export WB_DEMO_MODE=1               # 1 — выдуманные отзывы, сеть не нужна
python bot.py
```

Для YandexGPT понадобятся `YANDEX_FOLDER_ID` + `YANDEX_API_KEY`, для OpenAI — `OPENAI_API_KEY`. На Windows — `run_bot2.cmd` (токен из корневого `.env`).

## Из чего состоит

```
bot.py          — команды и обработка
llm.py          — цепочка провайдеров, вызов LLM, retry при невалидном JSON
reviews.py      — парсинг отзывов WB, TTL-кэш, retry на сетевые ошибки
models.py       — pydantic-модели: ответ LLM, распределение тональностей
db.py           — SQLite: история анализов
middlewares.py  — троттлинг и логирование
config.py       — настройки из переменных окружения
tests/          — 7 тестов (валидация JSON, цепочка фолбэков, распределение)
```

## Грабли, которые я здесь собрал

- **LLM не умеет возвращать валидный JSON на полном серьёзе.** Были ответы вида «Вот анализ: ...» вместо чистого JSON. Решение — переспрашивать с указанием ошибки pydantic, а после N попыток возвращать понятное сообщение вместо падения.
- **Публичное API WB для отзывов** (`feedbacks1.wb.ru`) тоже под антиботом (см. честные примечания в корневом README) — потому `WB_DEMO_MODE`.
- **Валидация на выходе важнее валидации на входе** — pydantic здесь не для юзер-инпута, а как «предохранитель» от мусора нейросети.
